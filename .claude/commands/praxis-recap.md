Give the user a fast, human recap of this project's PRAXIS memory.

1. Read `.praxis/memory.md`.
2. Summarize out loud, in this order, skipping empty parts:
   - **The project** — one line: what it is, the stack.
   - **Standing rules** — constraints and load-bearing things to never break.
   - **Recent work** — the last 2–3 session-log entries, one line each.
   - **Open threads** — anything marked in progress or unresolved.
3. Keep the whole recap under ~10 lines. No file dumps, no headers copied verbatim — talk like a teammate catching someone up.
4. End with: what looks like the most sensible next step, in one sentence.

If `.praxis/memory.md` does not exist in this project, stop and tell the user to run `npx praxis-memory` here first — one command, works on Windows, macOS and Linux.
